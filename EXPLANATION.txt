 1. PROJECT OVERVIEW
================================================================================

This is a PHP-based web application that implements IMAGE STEGANOGRAPHY —
the art of hiding secret data INSIDE an ordinary-looking PNG/JPEG image.

Key distinguishing features:
  • Files are ENCRYPTED (AES-256-GCM) before being hidden, so even if someone
    extracts the raw image pixels they only see random ciphertext.
  • Compression (zlib DEFLATE level 9) is applied before encryption so the
    hidden payload consumes fewer pixels, allowing smaller cover images.
  • The encrypted body is scattered RANDOMLY across the image using a
    password-derived PRNG (Fisher-Yates shuffle), resisting simple
    sequential pixel analysis.
  • A full user account system (register / login / password-reset-via-email)
    gates access to the encode/decode features.
  • All backend PHP modules are blocked from direct browser access via .htaccess.

 8. CRYPTOGRAPHIC ENGINE (crypto.php)
================================================================================

  ---- derive_master_key(string $password, string $salt): string ----

    Returns a 64-byte raw binary string using:
      hash_pbkdf2('sha256', $password, $salt, 100_000, 64, true)

    Breakdown:
      Algorithm  : SHA-256
      Iterations : 100,000 (NIST-recommended minimum for PBKDF2-SHA256)
      Output     : 64 raw bytes

    How the master key is split:
      bytes  0–31 → $encKey   (32 bytes) → used as the AES-256 key
      bytes 32–63 → $prngSeed (32 bytes) → used to seed the pixel shuffle PRNG

    Why 100,000 iterations?
      Makes brute-force attacks ~100,000x slower per guess. On a modern GPU that
      can do ~1 billion SHA-256 hashes/second, 100k iterations = ~10,000 guesses/sec,
      making large-scale cracking impractical vs shorter iteration counts.

    Determinism guarantee:
      Same $password + same $salt → always Same $encKey + Same $prngSeed.
      This is required for decoding (you need the same key you encrypted with).

  ---- aes_encrypt(string $plaintext, string $key, string $iv): array ----

    Returns [$ciphertext, $tag] where tag is always exactly 16 bytes.

    openssl_encrypt(
        $plaintext,
        'aes-256-gcm',
        $key,          ← 32-byte binary key
        OPENSSL_RAW_DATA,
        $iv,           ← 12-byte nonce (GCM standard)
        $tag,          ← output: 16-byte authentication tag
        '',            ← AAD (additional authenticated data) — not used
        16             ← tag length in bytes
    )

    AES-256-GCM is an AEAD (Authenticated Encryption with Associated Data) cipher:
      • Confidentiality: data is encrypted (nobody can read it without the key)
      • Integrity:       16-byte auth tag detects ANY tampering with the ciphertext

  ---- aes_decrypt(string $ciphertext, string $key, string $iv, string $tag): string ----

    openssl_decrypt(...)
    → If the tag doesn't match (wrong password or tampered image), returns false.
    → Throws RuntimeException('Invalid password or corrupted image')
    → Note: generic message intentional — don't reveal WHETHER it's wrong password
      vs corruption (security by ambiguity).

 9. DETERMINISTIC PRNG (prng.php)
================================================================================

  Purpose: Generate a deterministic random sequence of pixel indices for
  scattering the encrypted body across the image pixels.

  ---- prng_stream(string $seed, int $length): array ----

    Produces $length random bytes as an integer array [0..255].
    Algorithm:
      counter = 0
      loop until we have enough bytes:
        hash = SHA-256(seed || pack('N', counter))   ← 'N' = big-endian uint32
        take bytes from hash, increment counter

    This is counter-mode SHA-256 — a well-known stream-cipher construction.
    Same seed + same sequence of counter values → ALWAYS same output.

  ---- prng_int(string $seed, int $counter, int $max): int ----

    Returns a single integer in [0, max].
    Algorithm:
      hash = SHA-256(seed || pack('N', counter))
      val  = parse 4 bytes into a 31-bit positive integer (avoids float overflow)
      return val % (max + 1)
      
    Architecture Overflow Fix (32-bit vs 64-bit PHP):
      The 4 bytes of the hash are securely clamped into a 31-bit positive integer 
      (using bitwise shift and 0x7F masking). This guarantees that the number 
      never exceeds PHP_INT_MAX on 32-bit systems, avoiding float-modulo overflow
      and ensuring 100% deterministic encoding/decoding sequences across ALL 
      hardware architectures.

  How it ties into lsb.php:
    build_shuffle() calls prng_int() once per pixel to be shuffled.
    The pixel index list is shuffled in-place (Fisher-Yates partial shuffle).
    Since both encode and decode derive prngSeed the same way (same password),
    they produce identical shuffle sequences → matching pixel positions.

 10. PAYLOAD STRUCTURE (payload.php)
================================================================================

  HEADER FORMAT (always 33 bytes, always stored sequentially in LSB-1 mode):

    Byte  0:       lsb_mode (1 or 2) — determines how the BODY is embedded
    Bytes 1–16:    salt     (16 bytes) — PBKDF2 salt (random per encode)
    Bytes 17–28:   iv       (12 bytes) — AES-GCM nonce (random per encode)
    Bytes 29–32:   len      (4 bytes, big-endian uint32) — length of ciphertext

  Total header: 1 + 16 + 12 + 4 = 33 bytes.

  BODY (follows immediately after header in the payload binary string):
    Bytes 0 to (len-1):          ciphertext   (variable length)
    Bytes len to (len+15):       GCM auth tag (always 16 bytes)

  Pixel count needed for header:
    33 bytes × 8 bits = 264 bits
    Header always uses LSB-1 (1 bit per channel, 3 channels per pixel)
    264 / 3 = 88 pixels (rounded up = 88)

  ---- build_payload() ----
    Concatenates: chr(lsb) . salt . iv . pack('N', len) . ciphertext . tag
    Returns: single binary string (the complete payload to embed)

  ---- parse_header() ----
    Reads back those same offsets from the extracted header bytes.
    If data length < 33 bytes → throws RuntimeException (wrong image / corrupt).
    Returns array: ['lsb', 'salt', 'iv', 'len', 'offset']

  Security note — no magic signature:
    There is NO "STEG" marker or version byte at the start.
    Any file tested for steganographic content that is given the wrong password
    will simply fail AES-GCM tag verification — it does NOT reveal whether the
    image contains hidden data at all. This is "plausible deniability."

 11. LSB STEGANOGRAPHY ENGINE (lsb.php)
================================================================================

  Least-Significant Bit (LSB) steganography works by replacing the lowest
  bit(s) of each color channel value. A pixel with RGB (200, 128, 75) might
  become (201, 128, 74) — imperceptible to the human eye but storing hidden bits.

  ---- UTILITY FUNCTIONS ----

  bytes_to_bits(string $data): array
    Converts binary string to a flat array of 0s and 1s, MSB-first.
    Example: chr(0b10110010) → [1, 0, 1, 1, 0, 0, 1, 0]

  bits_to_bytes(array $bits): string
    Reverses the above: groups of 8 bits → byte → chr().

  ---- IMAGE I/O ----

  load_image_gd(string $imagePath): [$img, $width, $height]
    Loads PNG or JPEG using imagecreatefrompng() / imagecreatefromjpeg().
    Alpha channels are flattened: creates a new truecolor canvas, fills it white,
    then imagecopy() blends the source onto it. This ensures we operate only on
    solid RGB values (the steganographic bits operate on RGB, not alpha).
    Returns a GD image resource + dimensions.

  gd_to_png($img): string
    Captures imagepng() output via output buffering → returns PNG binary string.
    Output is ALWAYS PNG regardless of input type (PNG is lossless — JPEG is
    lossy compression which would destroy steganographic bits on re-save).

  ---- PIXEL HELPERS ----

  get_pixel($img, int $index, int $width): [R, G, B]
    Converts flat pixel index (y*width + x) → imagecolorat() → splits RGB channels.

  set_pixel($img, int $index, int $width, R, G, B): void
    Packs RGB channels back → imagesetpixel() at computed x,y.

  ---- PRNG SHUFFLE ----

  build_shuffle(int $start, int $total, int $needed, string $prngSeed): SplFixedArray
    Creates a SplFixedArray of pixel indices from $start to $total-1.
    Applies Fisher-Yates partial shuffle on the first $needed elements.
    Each swap position is chosen via prng_int(seed, counter, remaining_range).

    SplFixedArray is used instead of PHP array for ~4x memory savings.
    For a 1920×1080 image (2,073,600 pixels), an int array would be ~64MB.
    SplFixedArray uses ~8MB for the same data.

  ---- EMBEDDING ----

  embed_lsb(string $imagePath, string $payload, int $lsbMode, string $prngSeed): string

    Step 1 — Split payload:
      headerBytes = payload[0..32]    (33 bytes)
      bodyBytes   = payload[33..]     (ciphertext + tag)

    Step 2 — Convert to bits:
      headerBits = bytes_to_bits(headerBytes)
      bodyBits   = bytes_to_bits(bodyBytes)

    Step 3 — Calculate pixel counts needed:
      headerPixelsNeeded = ceil(264 / 3)               ← always ~88 pixels
      bodyPixelsNeeded   = ceil(bodyBits / (3 * mode)) ← depends on lsbMode

    Step 4 — Embed header (SEQUENTIAL, always LSB-1):
      For each of the 88 header pixels (starting from pixel 0):
        Get [R, G, B]
        R = (R & 0xFE) | headerBits[i++]    ← replace bit 0 of R
        G = (G & 0xFE) | headerBits[i++]    ← replace bit 0 of G
        B = (B & 0xFE) | headerBits[i++]    ← replace bit 0 of B
        Write back [R, G, B]

    Step 5 — Embed body (PRNG-SHUFFLED):
      Build shuffle of pixels from index 88 onward.
      For each shuffled pixel:
        Get [R, G, B]
        For bit position i in 0..lsbMode-1:  ← lsbMode=1: only bit 0; lsbMode=2: bits 0 and 1
          R = (R & ~(1<<i)) | (bodyBits[j++] << i)
          G = (G & ~(1<<i)) | (bodyBits[j++] << i)
          B = (B & ~(1<<i)) | (bodyBits[j++] << i)
        Write back [R, G, B]

    Step 6:
      Convert GD image to PNG binary string. Return it.

    LSB Mode comparison:
      LSB-1 (Sharing Image):   1 bit  per channel × 3 channels = 3 bits per pixel
                               Lower distortion — suitable for sharing online.
      LSB-2 (My Device):       2 bits per channel × 3 channels = 6 bits per pixel
                               Double capacity — suitable for local storage.

  ---- HEADER EXTRACTION ----

  extract_lsb(string $imagePath): array
    Reads LSB (bit 0) of each channel from the first ~88 pixels sequentially.
    Reassembles 33 bytes of header. Returns those bytes + metadata.

  ---- BODY EXTRACTION ----

  extract_lsb_body(imagePath, headerPixelsUsed, lsbMode, prngSeed, bodyLenBytes): string
    Reproduces the EXACT same shuffle using the same prngSeed and counter values.
    Reads bits from those shuffled pixels in the same order as they were written.
    Returns the raw body bytes (ciphertext + auth tag concatenated).

 12. ENCODE PIPELINE (process_encode.php)
================================================================================

  This file is a pure POST endpoint — it receives a multipart form submission
  and returns either a PNG binary stream (success) or plain text error (failure).
  It NEVER outputs HTML.

  PHP settings applied at top:
    error_reporting(E_ALL), display_errors=0, log_errors=1
    memory_limit=512M     ← GD pixel operations are memory-intensive
    set_time_limit=180    ← Allow up to 3 minutes for large images

  Output buffering (ob_start):
    ALL output is buffered immediately. Before sending the PNG, the buffer is
    cleared so no stray whitespace or PHP notices contaminate the binary stream.

  STEP-BY-STEP FLOW:
  ──────────────────
  1. Start session, include crypto.php / prng.php / payload.php / lsb.php.

  2. AUTH CHECK:
     $_SESSION['user_id'] must exist and be non-empty.
     → HTTP 403 "Access Denied" if not logged in.

  3. METHOD CHECK:
     Only POST is accepted. GET → HTTP 405.

  4. CSRF CHECK:
     hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])
     → Uses constant-time comparison to prevent timing attacks.

  5. COVER IMAGE VALIDATION:
     $_FILES['cover_image']['error'] === UPLOAD_ERR_OK
     getimagesize($coverPath)  must return IMAGETYPE_PNG or IMAGETYPE_JPEG
     If JPEG is detected, its MIME type is shown in the error for clarity.
     Max size: 20 MB (prevents memory exhaustion in GD).

  6. PASSWORD:
     $_POST['password'] must be non-empty. (Complexity rules enforced client-side;
     PHP enforces non-empty only since the hash is deterministic regardless.)

  7. LSB MODE:
     $_POST['lsb_method'] must be "1" or "2". Cast to int. Invalid → RuntimeException.

  8. SECRET FILES:
     $_FILES['secret_files'] must exist.
     Max 15 files. Max total size 10 MB.
     All files are added to a temporary ZipArchive:
       basename($files['name'][$i]) → sanitized with preg_replace('/[^a-zA-Z0-9._-]/', '_', $name)
       zip->addFile($tmpPath, $safeName)

  9. COMPRESSION:
     $plaintext = gzcompress($zipBytes, 9)
     Level 9 = maximum DEFLATE compression.
     Reduces payload size → fewer pixels needed → works with smaller images.

  10. CAPACITY CHECK:
      totalPixels = width × height
      headerPixels = ceil((33 × 8) / 3) = 88
      bodyBytes = strlen($compressed) + 16  (ciphertext + auth tag)
      bodyPixels = ceil((bodyBytes × 8) / (3 × lsbMode))
      If headerPixels + bodyPixels > totalPixels → RuntimeException with helpful tip.

  11. KEY DERIVATION:
      $salt = random_bytes(16)       ← fresh random salt per encode
      $derived = derive_master_key($password, $salt)   ← 64 bytes via PBKDF2
      $encKey   = substr($derived,  0, 32)
      $prngSeed = substr($derived, 32, 32)
      $iv = random_bytes(12)         ← fresh random IV per encode

  12. ENCRYPTION:
      [$ciphertext, $tag] = aes_encrypt($plaintext, $encKey, $iv)

  13. PAYLOAD BUILD:
      $payload = build_payload($lsbMode, $salt, $iv, $ciphertext, $tag)

  14. EMBED:
      $stegoImageData = embed_lsb($coverPath, $payload, $lsbMode, $prngSeed)

  15. OUTPUT:
      header('Content-Type: image/png')
      header('Content-Disposition: attachment; filename="stego_image.png"')
      header('Content-Length: ' . strlen($stegoImageData))
      echo $stegoImageData;
      exit;

  ERROR HANDLING (catch Throwable):
    Any exception at ANY step: ob_end_clean(), HTTP 400, echo $e->getMessage(), exit.
    The JS in home.php reads this text and shows it in an alert().


================================================================================
 13. DECODE PIPELINE (process_decode.php)
================================================================================

  Mirror image of process_encode.php. Returns ZIP binary or plain text error.

  PHP settings: same as encode (512M memory, 180s time limit, ob_start).

  STEP-BY-STEP FLOW:
  ──────────────────
  1. Include same 4 backend modules. Start session.
  2. AUTH CHECK: same as encode.
  3. METHOD CHECK: POST only.
  4. CSRF CHECK: same constant-time comparison.

  5. STEGO IMAGE VALIDATION:
     $_FILES['stego_image'] must upload correctly.
     Max 10 MB (stego images only carry encode output, naturally smaller).
     Must be IMAGETYPE_PNG. (JPEG cannot be decoded — lossy compression destroys bits.)

  6. PASSWORD: Must be non-empty.

  7. EXTRACT HEADER:
     $headerInfo = extract_lsb($stegoPath)
     → Reads LSB-1 from first ~88 pixels, returns 33 bytes of header data.
     $header = parse_header($headerInfo['header_bytes'])
     → Returns: ['lsb', 'salt', 'iv', 'len', 'offset']

  8. SANITY CHECKS (before expensive PBKDF2 computation):
     $header['lsb'] must be 1 or 2.
     $header['len'] must be > 0 and ≤ 10 MB.
     These catch obviously corrupted images without PBKDF2 overhead.

  9. KEY DERIVATION:
     Same formula as encode using the salt extracted from the header.
     $derived = derive_master_key($password, $salt)
     $encKey   = substr($derived,  0, 32)
     $prngSeed = substr($derived, 32, 32)

  10. EXTRACT BODY:
      $bodyLen = $header['len'] + 16      ← ciphertext + 16-byte auth tag
      $bodyBytes = extract_lsb_body(
          $stegoPath,
          $headerInfo['header_pixels_used'],
          $header['lsb'],
          $prngSeed,
          $bodyLen
      )

  11. SPLIT BODY:
      $ciphertext = substr($bodyBytes, 0, $header['len'])
      $tag        = substr($bodyBytes, $header['len'], 16)

  12. DECRYPT:
      $plaintext = aes_decrypt($ciphertext, $encKey, $header['iv'], $tag)
      Wrong password → tag mismatch → RuntimeException("Invalid password or corrupted image")

  13. DECOMPRESS:
      $zipData = gzuncompress($plaintext)
      → Reverses the gzcompress(level 9) from encoding.
      → False return → RuntimeException.

  14. OUTPUT:
      header('Content-Type: application/zip')
      header('Content-Disposition: attachment; filename="secret.zip"')
      echo $zipData;
      exit;

  The downloaded secret.zip always contains the original file(s).
  The user extracts the ZIP manually to get their file(s) back.

 14. USER AUTHENTICATION

  14a. REGISTRATION (register.php)
  ─────────────────────────────────

    samesite  = Strict       ← Cookie not sent on cross-site requests (CSRF protection)

    username: 3–50 chars, only [a-zA-Z0-9_], required.

    SELECT id FROM users WHERE email = ?
    If found → show error. No insert.

    $hashed = password_hash($password, PASSWORD_DEFAULT)
    → Uses bcrypt (PHP default) with work factor ~12.
    → NEVER stored in plaintext.

  Auto-login on success:
    $userId = $pdo->lastInsertId()
    session_regenerate_id(true)   ← Prevents session fixation attack
    $_SESSION['user_id']    = $userId
    $_SESSION['username']   = $username
    $_SESSION['last_activity'] = time()
    header("Location: home.php"); exit;

    Checks all password rules in real-time (regex on keypress).
    Shows ✔ / ● indicators for each rule.

    NOTE: Client-side is UX only — PHP server-side validation is the real guard.

  Processing overlay (common to all auth pages):
    On submit: shows a full-screen spinner animation, disables the button,
    then calls form.submit() to do the actual POST.

  14b. LOGIN (login.php)
  ───────────────────────
  Same session cookie settings as register.php.

  POST flow:
    1. CSRF check (hash_equals).
    2. Trim email, get password.
    3. SELECT id, username, password_hash FROM users WHERE email = ?
    4. password_verify($password, $row['password_hash'])
       → bcrypt comparison. Timing-safe (bcrypt is inherently constant-time).
    5. SUCCESS:
       session_regenerate_id(true)
       Set $_SESSION['user_id'], username, last_activity.
       Redirect to home.php.
    6. FAILURE:
       Generic error "Invalid access credentials." (same message regardless of
       whether email exists or password is wrong — anti-enumeration).
       sleep(1) — delays automated brute-force attempts by 1 second.

  Password-reset success message:
    If $_GET['reset'] === '1' (set by verify_reset.php after success):
    Shows "Password updated successfully. Access system with new credentials."

  14c. LOGOUT (logout.php)
  ─────────────────────────
  1. session_start() if not already started.
  2. $_SESSION = []           ← Clear all session variables.
  3. setcookie(session_name(), '', time()-3600, ...)  ← Expire the session cookie.
  4. session_destroy()        ← Destroy server-side session file.
  5. header("Location: home.php"); exit;
     → User lands on home.php as a guest.

 15. PASSWORD RESET SYSTEM
================================================================================

  15a. REQUEST RESET (request_reset.php + request_reset.js)
  ───────────────────────────────────────────────────────────
  Security headers set by PHP (stricter than .htaccess global):
    Referrer-Policy: no-referrer
    X-Frame-Options: DENY
    X-Content-Type-Options: nosniff
    Content-Security-Policy: ... script-src 'self' (no unsafe-inline)

  HTTPS enforcement with localhost exception:
    if (!$isSecure && !$isLocalhost):
      301 redirect to https:// equivalent.
    Localhost is detected by checking REMOTE_ADDR, HTTP_HOST.

  CSRF generation (before any POST logic):
    if (empty($_SESSION['csrf_token'])):
        $_SESSION['csrf_token'] = bin2hex(random_bytes(32))
    Generated BEFORE POST block ensures token always exists when CSRF check runs.

  Anti-enumeration protection:
    $generic_message = "If the email exists, a password reset link has been sent."
    This message is ALWAYS shown after POST, regardless of success or failure.
    An attacker cannot tell if the email is registered or not.

  POST flow (when email submitted):
    1. CSRF check.
    2. Trim email, validate length ≤ 255 and FILTER_VALIDATE_EMAIL.
    3. DELETE expired tokens from password_resets.
    4. DELETE old rate-limit records (> 24 hours).
    5. COUNT reset attempts for this email in last 1 hour.
       If ≥ 3 → skip (but still show generic message).
    6. If < 3 attempts:
       a. INSERT attempt into password_reset_attempts.
       b. Look up user by email.
       c. If user exists:
          - Generate token = bin2hex(random_bytes(32))  ← 64 hex chars, 256-bit entropy
          - token_hash = hash('sha256', $token)         ← SHA-256 of raw token
          - Capture IP + User-Agent.
          - DELETE any existing tokens for this email.
          - INSERT new row: (email, token_hash, NOW()+30min, ip, ua)
          - Build reset link: http://host/steganography/verify_reset.php?token=RAW_TOKEN
          - Send email via PHPMailer:
              $mail->isSMTP()
              $mail->Host = smtp.gmail.com (from .env)
              $mail->SMTPAuth = true
              $mail->Username / Password from .env
              $mail->SMTPSecure = STARTTLS, Port = 587
              HTML body with clickable link. AltBody for plain-text email clients.
       d. Mailer exceptions are caught and logged to error_log (not shown to user).

  request_reset.js:
    Intercepts form submit. If form is valid → shows overlay animation → form.submit().

  15b. VERIFY RESET (verify_reset.php + verify_reset.js)
  ────────────────────────────────────────────────────────
  Accessed via: verify_reset.php?token=RAW_TOKEN

  GET phase (page load):
    1. Hash the token from URL: hash('sha256', $_GET['token'])
    2. Query: SELECT ... FROM password_resets WHERE token_hash=? AND expires_at>NOW() AND used=0
    3. If row found:
       a. IP + User-Agent binding check (hash_equals for constant-time comparison).
          If current IP ≠ stored IP OR current UA ≠ stored UA → deny.
          This prevents token theft (e.g., link forwarded to another device).
       b. Rate-limit check via reset_verify_attempts (10 per IP per hour).
    4. If binding fails or token not found → $fatal_error = "Security Error: ..."
       → Shows error message and "REQUEST NEW LINK" button. Form is NOT shown.

  POST phase (new password submission):
    1. CSRF check.
    2. Confirm passwords match.
    3. Validate password complexity:
       len ≥ 8, uppercase, lowercase, digit, special char.
    4. $pdo->beginTransaction()  ← Both queries must succeed or neither does.
    5. UPDATE users SET password_hash = ? WHERE email = ?
    6. UPDATE password_resets SET used = 1 WHERE email = ? AND token_hash = ?
       → Marks token as used — prevents replay attacks (reusing the same link).
    7. $pdo->commit()
    8. session_unset() + session_destroy()  ← Clean slate after reset.
    9. header("Location: login.php?reset=1"); exit;

  verify_reset.js:
    Real-time password rule checks (same as register.php but implemented separately).
    Submit button disabled until all rules pass (visual feedback via opacity/cursor).
    checkFormState() runs on every keyup.
    On submit: shows overlay, re-validates, then form.submit().

  Replay Attacks           token.used flag set to 1 after successful reset

                           Real errors logged to server error_log only
  Directory Listing        Options -Indexes in .htaccess

================================================================================
 23. COMPLETE DATA-FLOW: ENCODE
================================================================================

  [Browser: home.php]
    User selects:
      cover.png     (e.g. 1920×1080 = 2,073,600 pixels)
      secret.pdf    (500 KB)
      lsb_method=1  (Sharing Image / LSB-1)
      password="MyP@ss123"

  [Browser JS: submitEncode()]
    Validates password rules client-side.
    Builds FormData. POSTs to process_encode.php with multipart/form-data.

  [process_encode.php]
    ① ZIP:
       ZipArchive: adds secret.pdf → stegzip_XXXXX (temp .zip)
       zipBytes = file_get_contents(tempZip)        ← e.g. 510 KB (ZipArchive overhead)

    ② COMPRESS:
       plaintext = gzcompress(zipBytes, 9)           ← e.g. 490 KB (compressed)

    ③ CAPACITY CHECK:
       headerPixels = ceil((33×8)/3) = 88
       bodyBytes = 490 KB + 16 = 501,776 bytes
       bodyPixels (LSB-1) = ceil(501776×8 / 3) = 1,338,069 pixels
       total needed = 88 + 1,338,069 = 1,338,157 ≤ 2,073,600 ✓

    ④ KEY DERIVATION:
       salt = random_bytes(16)       → e.g. 0xA3B2...
       iv   = random_bytes(12)       → e.g. 0xC4D5...
       masterKey = PBKDF2(sha256, "MyP@ss123", salt, 100000, 64)
       encKey   = masterKey[0..31]
       prngSeed = masterKey[32..63]

    ⑤ ENCRYPTION:
       [ciphertext, tag] = AES-256-GCM(plaintext, encKey, iv)
       → ciphertext ≈ 490 KB, tag = 16 bytes

    ⑥ PAYLOAD BUILD:
       payload = chr(1) . salt(16) . iv(12) . pack('N', 501760) . ciphertext . tag
       total payload length = 33 + 501760 + 16 = 501,809 bytes

    ⑦ LSB EMBED:
       Header (33 bytes = 264 bits):
         Written to pixels 0–87 using 1 bit per channel.
       Body (501,760 + 16 = 501,776 bytes = 4,014,208 bits):
         build_shuffle(88, 2073600, 1338069, prngSeed) → shuffled pixel order
         Write 1 bit per channel per pixel across 1,338,069 pixels.

    ⑧ OUTPUT:
       imagepng() the modified GD resource → binary PNG bytes.
       Send as attachment: stego_image.png.

  [Browser JS: submitEncode() after fetch]
    Creates blob URL → triggers <a> download → stego_image.png saved to disk.
    Alert "Encoding successful!"


================================================================================
 24. COMPLETE DATA-FLOW: DECODE
================================================================================

  [Browser: home.php]
    User selects:
      stego_image.png   (the file from step 20 above)
      password = "MyP@ss123"

  [Browser JS: submitDecode()]
    Builds FormData. POSTs to process_decode.php.

  [process_decode.php]
    ① EXTRACT HEADER (LSB-1 sequential):
       Read 88 pixels starting from pixel 0.
       Extract bit 0 from each R, G, B channel.
       Reassemble 33 bytes = [lsb=1, salt=0xA3B2..., iv=0xC4D5..., len=501760]

    ② PARSE HEADER:
       lsb      = 1
       salt     = 16 bytes
       iv       = 12 bytes
       len      = 501,760 (ciphertext length)

    ③ SANITY CHECK:
       lsb ∈ {1,2} ✓
       len ∈ (0, 10×1024×1024] ✓

    ④ KEY DERIVATION (with extracted salt):
       masterKey = PBKDF2(sha256, "MyP@ss123", extracted_salt, 100000, 64)
       encKey   = masterKey[0..31]
       prngSeed = masterKey[32..63]
       (These are EXACTLY the same values as during encoding)

    ⑤ EXTRACT BODY:
       bodyLen = 501760 + 16 = 501,776 bytes
       Reproduce build_shuffle(88, 2073600, 1338069, prngSeed)
       → same shuffled pixel list as encoding.
       Read bits from those pixels → 501,776 bytes.

    ⑥ SPLIT BODY:
       ciphertext = bodyBytes[0..501759]  (501,760 bytes)
       tag        = bodyBytes[501760..501775]  (16 bytes)

    ⑦ DECRYPT:
       AES-256-GCM-Decrypt(ciphertext, encKey, iv, tag)
       → tag matched → returns compressed bytes (490 KB)

    ⑧ DECOMPRESS:
       zipData = gzuncompress(compressedBytes)
       → original ZIP bytes restored (510 KB)

    ⑨ OUTPUT:
       Content-Type: application/zip
       Content-Disposition: attachment; filename="secret.zip"
       echo zipData; exit;

  [Browser JS: submitDecode() after fetch]

================================================================================
 25. KNOWN LIMITS & CONSTRAINTS
================================================================================

  1. JPEG INPUT → PNG OUTPUT ONLY:
     Encoding always outputs PNG (lossless). You cannot re-encode into a JPEG
     because JPEG's lossy compression destroys LSB data. If you share the stego
     image and a platform recompresses it as JPEG, the hidden data IS LOST.

  2. MAX SECRET SIZE = 10 MB (total of all files combined).
     This is enforced both server-side (process_encode.php) and client-side
     (updateCapacityDisplay warns when limit is approached).

  3. MAX COVER IMAGE = 20 MB file size.
     A 20 MB JPEG typically corresponds to a resolution well over 20 megapixels.

  4. MAX FILES = 15 per encode operation.
     If you need more, ZIP them first, then upload the single ZIP.

  5. SAME PASSWORD FOR ENCODE AND DECODE:
     The PRNG seed and AES key are both derived from the password + embedded salt.
     You MUST use the exact same password for decoding that was used for encoding.
     There is no recovery mechanism if the password is forgotten.

  6. LSB MODE IS SELF-DESCRIBING:
     The lsb_mode is stored in byte 0 of the header. The decoder reads it first
     and applies the correct bit-depth for extraction automatically.
     You do NOT need to tell the decoder which mode was used for encoding.

  7. NO STEGANALYSIS RESISTANCE BEYOND AES/PRNG:
     Advanced statistical analysis of pixel distributions (Chi-square test,
     RS Analysis, etc.) may detect LSB modification. The system provides strong
     cryptographic confidentiality but not statistical imperceptibility.

  8. LOCALHOST ONLY BY DEFAULT:
     HTTPS is enforced for request_reset.php and verify_reset.php but localhost
     is whitelisted. For production use, enable HTTPS/SSL and remove the localhost
     exception.

  9. NO MULTI-USER ISOLATION:
     All users share the same database tables. One user's encode/decode cannot
     access another's data (images are downloaded, not stored server-side).

  10. IMAGES ARE NOT STORED SERVER-SIDE:
      process_encode.php reads the uploaded image from PHP's tmp dir, processes
      it in memory, and streams the result back. Nothing is written to disk
      permanently. Tmp files are cleaned up by PHP automatically.
